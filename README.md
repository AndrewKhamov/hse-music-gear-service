# Учебные дедлайны

Небольшой FastAPI-сервис для личного учёта дедлайнов по учебе. Он позволяет добавлять и хранить информацию о дедлайнах: предмет, дату и описание (информация сохраняется в JSON-файл). 
Сервис позволяет получить информацию о предметах, по которым в данный момент есть актуальные задачи, а также сами будущие дедлайны, отсортированные по времени.

Срок задаётся датой YYYY-MM-DD. Сегодняшний дедлайн актуален весь день, включая 23:59. Со следующего дня он исчезает из обычного списка, но остаётся в файле и может быть получен по id. Приложение использует календарную дату компьютера, на котором запущено.

## Установка

Нужны Python 3.12 и Git. Команды выполняются в Ubuntu из корня проекта.

Сначала клонируйте репозиторий, подставив его настоящий адрес вместо YOUR_USERNAME/YOUR_REPOSITORY:

```bash
git clone https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git hse-study-deadlines
cd hse-study-deadlines
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt -r requirements-dev.txt
cp -n .env.example .env
cp -n deadlines.example.json deadlines.json
```

## Настройки

В локальном `.env` задаются:

| Переменная | Назначение | Значение по умолчанию без настройки |
|---|---|---|
| APP_NAME | Название сервиса | Учебные дедлайны |
| APP_AUTHOR | Автор | Не указан |

Приложение загружает `.env` через `load_dotenv()`. В шаблоне указан автор Your Name — замените его своим именем. После изменения настроек перезапустите сервер. Проверить значения можно через `/info`.

## Запуск

Обычный запуск:

```bash
python -m uvicorn app_final:app --host 127.0.0.1 --port 8000
```

При разработке можно добавить `--reload` для автоматической перезагрузки после сохранения кода. Остановка — Ctrl+C.

Документация и формы запросов: http://127.0.0.1:8000/docs.

## Маршруты

| Метод и путь | Назначение |
|---|---|
| GET / | Короткое описание |
| GET /health | Ответ `{"status":"ok"}` |
| GET /version | Версия приложения |
| GET /info | Название и автор из окружения |
| POST /deadlines | Добавить дедлайн: subject, due_date, description |
| GET /deadlines | Сегодняшние и будущие дедлайны по возрастанию даты |
| GET /deadlines/{deadline_id} | Запись по числовому ID, в том числе прошедшая. Для подробной информации |
| GET /subjects | Предметы, по которым есть актуальные дедлайны без повторений |

Для добавления откройте POST /deadlines в `/docs`, нажмите Try it out и заполните три поля. Дата — сегодня или позже, например 2030-12-01; замените её своим сроком. Нажмите Execute. Ответ 201 содержит ID новой записи. Повторный запрос создаст ещё одну запись.

Поля передаются как параметры URL, а не JSON-тело. Для просмотра записи подставьте её ID в GET /deadlines/{deadline_id}. Удаление, редактирование и отметка выполнения в этой версии не предусмотрены.

## Проверка и логи

При работающем сервере выполните в другом терминале:

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/version
curl http://127.0.0.1:8000/deadlines
```

Логи Uvicorn видны в терминале сервера: запуск, запросы, коды ответов и ошибки.

| Проблема | Что проверить |
|---|---|
| Could not import module | Запуск из корня проекта; файл называется app_final.py, команда содержит app_final:app |
| Connection refused | Запущен ли сервер, совпадает ли порт |
| FileNotFoundError на /deadlines | Есть ли deadlines.json в рабочей папке; при первой установке скопируйте пример |
| JSONDecodeError | Синтаксис JSON: двойные кавычки, запятые, отсутствие комментариев |
| 400 при добавлении | Дата уже прошла либо предмет/описание пусты |
| 404 при получении записи | Такого числового ID нет |
| 422 | Пропущен параметр или неверен формат даты/ID; POST принимает параметры URL |
| Пустой список | Все сроки прошли; проверьте дату компьютера и содержимое файла |

## Тесты

```bash
python -m pytest -v
```

Четыре теста проверяют health, отбор и сортировку актуальных заданий, создание с последующим чтением по ID и отклонение неправильной даты. Ожидаемый результат — `4 passed`. 

Два теста с хранилищем создают данные во временных папках pytest. Личный deadlines.json не изменяется. Даты рассчитываются относительно текущего дня.

## GitHub Actions и артефакт

Файл `.github/workflows/ci.yml` запускает CI при push и pull request. В одной задаче последовательно устанавливаются зависимости, выполняются тесты и сохраняется артефакт `study-deadlines-service`. При ошибке тестов шаг сохранения пропускается.

Артефакт можно скачать со страницы успешного запуска во вкладке Actions. Он содержит код, тесты, зависимости, README и шаблоны настроек/данных. Это архив исходников, а не постоянно работающий сервер.

## Хранение данных и ограничения

Рабочие записи находятся в `deadlines.json`: счётчик next_id и список deadlines. Добавленные задания сохраняются после перезапуска. Не заменяйте рабочий файл шаблоном при каждом запуске.

Личные `.env` и `deadlines.json` исключены из Git; публикуются только `.env.example` и `deadlines.example.json`. 

Сервис рассчитан на одного пользователя и последовательные изменения в одном экземпляре приложения. Простое JSON-хранилище не предназначено для одновременной записи несколькими запросами. Перед ручным изменением файла остановите сервер.
